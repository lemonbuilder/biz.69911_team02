## 역할 돌리기

서로 다른 생각이 오가도록, 세 사람이 대화 속 역할을 돌아가며 맡습니다.

- 말 꺼내기 · 되짚기 · 다르게 보기, 세 역할이 한 차례마다 한 칸씩 돕니다.
- 차례마다 말 꺼내기가 먼저 시작하고, 되짚기와 다르게 보기는 그 이야기에 자유롭게 반응해요.
- 이야기 하나가 일단락되면 "다음 차례"를 눌러 주세요.
- 역할이 버거우면 "이번엔 쉬어요"를, 역할 없이 이야기하고 싶으면 "역할 없이 계속"을 누르면 됩니다.
- 이 화면은 대화를 듣지도, 기록하지도 않습니다.

> 이기거나 설득하려는 자리가 아니에요. 서로 다른 생각을 발견하려는 자리예요.
> 처음 만난 사람과의 깊은 대화는 생각보다 덜 어색하고, 상대는 생각보다 내 이야기에 관심이 있다고 해요.
> 조언은 부탁받았을 때만 해 주세요.

이 소개와 약속 세 줄은 앱 시작 화면 위쪽과 프로토타입 README 맨 앞에 그대로 쓴다. 약속의 둘째 줄은 연구 결과(Kardas 외 2022)이고, 첫째·셋째 줄은 ChatGPT 대화에서 나온 원칙이다. 참여자에게 보이는 이름은 "역할 돌리기"이고, WhyTree 노드 이름 "발언 역할 순환"은 spec 제목과 노드 연결에만 쓴다.

## 누구를 위한 것인가, 문제가 드러나는 순간

- **대상:** 진짜대화의 3인 모임에 앉은 참여자 세 명.
- **순간:** 대화가 한 방향으로만 흘러 다들 맞장구만 치고, 다른 관점이 나오지 않을 때. 처음 만난 사이일수록 "저는 좀 다르게 생각하는데요"를 꺼내기 어렵다.
- 발화가 한 사람에게 쏠리는 문제는 이 기능의 주 대상이 아니다. Facilitator의 쏠림 방지 규칙과 Recap의 발화 비율이 이미 다룬다. 역할이 돌면서 따라오는 효과로만 본다.

## WhyTree에서 맡는 노드

- **주 노드:** 발언 역할 순환 (새로운 HOW, 점선 상자)
- **바로 위:** 다양한 의견 발견 → 자신의 생각 확장 → 자신의 세계 너머 발견
- **형제 노드:** 서로 다른 의견 듣기. "되짚기" 역할이 이 노드를 함께 건드린다.

## 팀원 기능과의 경계

| | Facilitator (박혜민) | Recap (정직한) | 역할 돌리기 (문피아) |
|---|---|---|---|
| 정하는 것 | 무엇을 이야기할지 (질문) | 끝난 뒤 실제로 한 역할 (관찰) | 대화 중에 어떻게 말할지 (맡을 역할) |
| 언제 | 대화 중 | 대화 후 | 대화 중, 첫 인사 뒤부터 |
| 녹음·AI | 세 명 동의 시 듣고 AI로 질문 생성 | 녹음 후 전사·분석 | 쓰지 않음 |
| 남기는 것 | 끝나면 이 기기에서 지움 | 분석 결과 | 없음 |

- Facilitator의 첫 질문 안내("한 사람씩 돌아가며 답해 보세요")는 **답하는 순서**다. 역할 돌리기는 그 뒤에 켜고, 순서가 아니라 **말하는 방식**을 정한다.
- Facilitator는 특정인을 지목하지 않는다. 역할 돌리기는 자리에 역할을 붙이지만, 무슨 이야기를 하라고는 하지 않는다.
- Recap이 보여 주는 관찰 라벨("질문하는 사람", "이어 주는 사람", "주로 말하는 사람")과 역할 이름이 겹치지 않게 했다. "맡은 역할"과 "실제로 한 역할"이 섞이지 않도록.
- 두 화면은 연동하지 않는다. 같은 노트북에서 따로 연다. Facilitator에서 "다음 질문"을 누를 때 "다음 차례"도 함께 누르라고 사람에게 안내만 한다.

## 원칙

- 대화는 사람이 나누고, 앱은 역할을 보여 줄 뿐이다.
- 앱은 먼저 끼어들지 않는다. 역할은 사람이 누를 때만 돌고, 소리·깜빡임으로 재촉하지 않는다.
- 다르게 보기는 반대 연기가 아니다. 마음에 없는 입장을 맡기면 "솔직한 생각 나누기"와 충돌한다. 실제로 떠오른 다른 경우만 꺼내고, 없으면 "저도 비슷해요"도 괜찮다. 진짜 소수 의견이 맡겨진 반대(악마의 대변인)보다 더 많고 나은 해결책을 끌어냈다는 연구가 이 결정을 지지한다 (Nemeth 외 2001).
- 화두는 던지되 고백을 요구하지 않는다. 깊은 대화는 생각보다 덜 어색하지만 (Kardas 외 2022), 자기 실패는 위협적이고 사람들은 실패를 드러내길 꺼린다 (Eskreis-Winkler & Fishbach 2019; Brooks 외 2019). 그래서 화두 문구는 들은 이야기로도 답할 수 있게 쓴다.
- 역할은 거절할 수 있다. 개인은 한 차례 쉬고, 테이블은 언제든 역할을 끈다.
- 듣지 않고, 기록하지 않고, 평가하지 않는다.

## 사용자가 하는 일 (단계별)

1. 노트북 Chrome에서 `public/index.html`을 연다. 노트북은 테이블 한쪽 끝에 두고 세 사람이 화면을 바라보며 반원으로 앉는다.
2. 시작 화면에서 소개와 약속을 읽는다. 오늘의 화두를 하나 고르거나 "화두 없이"를 고른다 (기본은 첫 화두인 실패). 부를 이름을 자리(화면을 바라볼 때 왼쪽·가운데·오른쪽)마다 적거나 비워 둔다.
3. 첫 인사(Facilitator의 아이스브레이킹 등)가 끝나면 누군가 "역할 시작"을 누른다. 화면 위에 화두와 그 화두의 첫 번째 질문이 뜨고, 세 자리에 역할이 무작위로 하나씩 뜬다.
4. "먼저 시작해요" 표시가 붙은 말 꺼내기가 먼저 이야기한다. 되짚기와 다르게 보기는 그 이야기에 순서 없이 자유롭게 반응한다. 자리(왼쪽·가운데·오른쪽)가 아니라 역할이 누가 먼저인지 정한다.
5. 질문 하나를 충분히 이야기했으면 누구든 "다음 차례"를 누른다. 모두 한 칸씩 같은 방향으로 옮겨 가고, 화두의 다음 질문이 뜬다. 세 번째 질문 다음부터는 화두만 남는다.
6. 역할이 버거운 사람은 자기 칸의 "이번엔 쉬어요"를 누른다. 그 칸이 흐려지고, 그 차례 동안 역할이 비어 있다. "다시 할게요"로 취소할 수 있다.
7. 역할 없이 이야기하고 싶으면 누구든 "역할 없이 계속"을 누른다. 역할 칸이 사라진다. "역할 다시 켜기"를 누르면 멈췄던 배정에서 이어 간다.
8. 모임이 끝나면 "끝내기"를 누른다. 입력한 이름을 지우고 끝 화면을 보여 준다.

## 역할 규칙

### 세 역할

| 역할 | 화면 설명 | 노리는 것 |
|---|---|---|
| 말 꺼내기 | 지금 이야기에 대한 내 생각이나 경험을 먼저 꺼내 주세요. 들은 이야기나 가벼운 경험이어도 괜찮아요. | 이야기의 출발점. 고백이 아니어도 되게 (Eskreis-Winkler & Fishbach 2019: 남의 실패에서도 자기 실패 못지않게 배운다) |
| 되짚기 | 방금 들은 말을 한 문장으로 되짚고 '이렇게 이해했는데 맞아요?' 하고 확인한 뒤, 궁금한 걸 하나 더 물어봐 주세요. | 다른 의견이 실제로 들리게 (형제 노드 "서로 다른 의견 듣기"). 짐작보다 직접 묻는 쪽이 정확하고 (Eyal 외 2018), 후속 질문이 호감을 예측한다 (Huang 외 2017) |
| 다르게 보기 | 다른 경우나 다른 시선이 떠오르면 하나 꺼내 주세요. 반대하라는 뜻은 아니에요. 떠오르지 않으면 '저도 비슷해요'도 괜찮아요. | 다른 관점이 나오게 (주 노드 "다양한 의견 발견") |

- 차례마다 말 꺼내기가 먼저 시작한다. 되짚기와 다르게 보기는 둘 다 앞의 이야기에 반응하는 역할이라 둘 사이의 순서는 정하지 않는다. (처음에는 순서를 전혀 정하지 않았는데, 화면에 순서가 없으니 누가 말할지 알 수 없다는 문피아의 지적이 나왔다. 순서가 정말 중요한 것은 누가 먼저 시작하느냐뿐이라 첫 번째만 정했다, 2026-10-30)
- 역할이 돌기 때문에 "반대만 하는 사람"이 따로 생기지 않는다.
- 후속 질문은 따로 역할을 만들지 않고 되짚기에 붙였다. 역할을 늘리면 Recap의 "질문하는 사람" 라벨과 겹친다.

### 화두

- 모임 전체에 걸친 화두 하나를 역할 칸 위에 고정한다. 화두마다 굵직한 질문 3개를 가벼운 것에서 깊은 것 순서로 두고, "다음 차례"를 누를 때마다 다음 질문으로 넘어간다. 질문 3개를 거치는 동안 모두가 세 역할을 한 번씩 맡는다. 세 번째 질문 다음부터는 화두만 보여 준다.
- 깊이를 한 단계씩 올리는 것은 Aron 외(1997)의 방식(15분씩 3세트, 점점 개인적인 질문)을 따른 것이다. 다만 그 연구는 2인이고, 쪽지 질문 36개가 45분을 이끌었다.
- **Facilitator와의 경계:** Facilitator는 대화 흐름에 맞춘 질문(AI) 또는 주제 없는 일반 질문을 하나씩 크게 띄우고, 깊이 단계는 사람이 고른다. 역할 돌리기는 고른 화두 하나를 파고드는 고정 질문 3개만 작게 보여 주고, 화면의 주인공은 역할이다. 대화에 맞춰 질문을 만들지 않는다.
- 화두 문구 규칙: 생각이 갈릴 수 있는 주제, 자기 고백을 요구하지 않음, 들은 이야기로도 답할 수 있음, 직업·회사·나이·사는 곳을 묻지 않음 (Facilitator 사전질문 기준과 맞춤).
- 화두 목록 (사람이 쓴 고정 목록, AI 사용 안 함):

| 화두 | 문구 |
|---|---|
| 실패 (기본) | 실패라고 생각했다가 나중에 다르게 보인 일이 있나요? 들은 이야기도 좋아요. |
| 잘 산다는 것 | 잘 산다는 건 어떤 모습일까요? 주변에서 본 모습도 좋아요. |
| 어른 | 어른이 된다는 건 무엇이 달라지는 걸까요? |
| 운과 노력 | 지금의 나를 만든 것 중 운은 얼마나였을까요? |
| 화두 없이 | 화면에 화두를 띄우지 않는다 |

- 화두별 질문 3개 (가벼움 → 깊음):

| 화두 | ① | ② | ③ |
|---|---|---|---|
| 실패 | 어떤 일을 '실패'라고 부르게 되나요? | 누군가는 실패라고 하는데 나는 다르게 본 일이 있나요? | 실패하지 않으려고 피해 온 게 있다면, 그건 무엇을 지키려는 걸까요? |
| 잘 산다는 것 | 요즘 '잘 지내고 있다'고 느끼는 순간은 언제인가요? | 잘 사는 것과 성공하는 것은 같을까요? | 나중에 잘 살았다고 말하려면 무엇이 있어야 할까요? |
| 어른 | 처음으로 '어른이 됐다'고 느낀 순간이 있나요? | 닮고 싶은 어른과 닮고 싶지 않은 어른은 무엇이 다를까요? | 어른이 되면서 잃은 게 있다면 무엇일까요? |
| 운과 노력 | 최근에 운이 좋았다고 느낀 일은 무엇인가요? | '노력하면 된다'는 말에 얼마나 동의하나요? | 내가 가진 운을 알게 되면, 남을 보는 눈이 달라질까요? |

- 화두와 질문 문구는 에이전트가 초안을 썼고, 문피아가 그대로 쓰기로 했다 (2026-10-30). 시범 모임 뒤 고친다.
- 화두는 시작할 때만 고른다. 도중에 바꾸는 기능은 P1.
- 대화 중 추가 질문은 앱이 띄우지 않는다. 되짚기 역할이 상대의 답을 듣고 묻는다 (Huang 외 2017의 후속 질문은 상대 답에 기반한 질문이고, 이 앱은 대화를 듣지 않는다).

### 순환

- 첫 배정은 무작위다. 사람이 고르게 하면 "다르게 보기"를 서로 미루는 순간이 생긴다.
- "다음 차례"를 누르면 모두 한 칸씩 같은 방향으로 이동한다. 세 차례면 모두가 세 역할을 한 번씩 맡는다.
- 다음 차례 예고는 띄우지 않는다. 지금 맡은 역할에 집중하게 하려는 것이다.
- "이번엔 쉬어요"는 그 역할을 비워 둘 뿐, 다른 사람과 맞바꾸지 않는다. 맞바꾸면 버거운 역할이 다른 사람에게 떠넘겨진다. 쉬기는 다음 차례에 풀린다. 쉰 이유는 묻지도 남기지도 않는다.
- 3명 고정이다.

## 화면

- 시작 화면의 이름 칸: 위에서 내려다본 테이블 그림 위에 둔다. 노트북은 테이블 위쪽 끝에 화면이 사람 쪽을 보게 그리고, 세 자리는 반원으로 왼쪽 · 가운데(아래) · 오른쪽에 그린다. 그림을 보는 사람이 화면을 바라보고 앉은 쪽이므로 그림의 왼쪽이 곧 "화면을 바라볼 때 왼쪽"이다. 각 자리 옆에 이름 칸이 있다 (문피아 요청, 2026-10-30).
- 역할 칸 위 가운데: "오늘의 화두"와 화두 문구(22px), 그 아래 지금 질문(28px, 앞에 "질문 1/3" 같은 작은 표시)을 고정한다. 세 번째 질문 다음부터는 화두만 남긴다. "화두 없이"를 골랐으면 아무것도 띄우지 않는다.
- 세 칸을 화면을 바라볼 때 왼쪽 · 가운데 · 오른쪽에 둔다. 실제 자리와 맞춘다.
- 칸마다 들어가는 것: 이름 또는 자리(18px), **역할 이름(44px)**, 한 줄 설명(20px), 작은 "이번엔 쉬어요". 차례마다 먼저 시작하는 **말 꺼내기** 칸에만 초록 테두리와 "먼저 시작해요" 표시를 붙인다. 이 강조는 말 꺼내기를 따라 차례마다 자리를 옮기므로 역할이 도는 것이 눈에 보인다. 되짚기와 다르게 보기 칸에는 순서 표시를 붙이지 않는다.
- 쉬는 칸은 역할과 설명을 흐리게 하고 "이번엔 쉬어요"를 표시한다.
- "다음 차례": 하단 가운데의 주 버튼.
- 위 오른쪽 구석: "모임 N분 · 이번 차례 N분째"를 작은 회색 글자로 표시한다 (15초마다 갱신, 첫 1분은 "1분째"). "모임 N분"은 역할 시작부터 센 전체 시간으로, 역할을 꺼도 계속 센다. 시간 실험(테스트 3·5)에서 종이에 옮겨 적는 데 쓴다.
- 아래 구석에 작게: 왼쪽 "역할 없이 계속", 오른쪽 "끝내기". 확인 창은 없다.
- 역할을 끈 동안: "지금은 역할 없이 이야기하는 중이에요."와 "역할 다시 켜기"만 보인다. "끝내기"는 그대로 오른쪽 구석에 있다.
- 끝 화면: "끝났습니다. 입력한 이름을 지웠습니다."와 "처음으로".
- 760px보다 좁으면 세 칸을 세로로 쌓는다 (프로토타입 확인용. 실제 쓰임은 노트북 한 대).

- 대화 중 앱이 추가 질문을 띄우는 것
- "한 차례 10분" 같은 시간 안내 (근거를 찾지 못함)
- 대화 전후 관점 기록 (Recap 회고와 겹치고, 기록하지 않는다는 원칙과 충돌)

## AI 모델과 실패했을 때

- **AI 모델: 없음.** 대화 중 녹음·음성 인식·AI를 쓰지 않는다 (`/grill-me` 시작 조건). API 키도 서버 호출도 없다.
- 실패할 수 있는 곳은 화면뿐이다. 노트북이 없거나 페이지가 열리지 않으면 P1의 인쇄용 역할 카드 3장으로 손으로 돌린다 (인쇄 카드는 아직 만들지 않음).
- 새로고침하거나 탭을 닫으면 저장한 것이 없으므로 이름과 배정이 사라지고, "역할 시작"부터 다시 무작위로 배정한다.

## 구현

- 위치: `prototypes/문피아/`
- 정적 페이지: `public/index.html` + `public/app.js` + `public/rotation.js`. 파일을 바로 열어도 동작하도록 모듈 import 대신 일반 `<script>`를 쓰고, `rotation.js`는 `globalThis.RoleRotation`에 붙인다.
- `rotation.js`: 순환 규칙만 담은 순수 함수 (`createRotation`, `assignments`, `nextTurn`, `toggleRest`). 난수를 주입받아 테스트할 수 있다.
- `serve.js`: 의존성 없는 정적 서버, 포트 3300 (팀원의 3000·3100과 겹치지 않게). `npm start`.
- 자동 테스트(`npm test`, Node 기본 테스트 러너): 첫 배정에 겹침 없음, 한 칸씩 같은 방향 이동, 세 차례면 세 역할 모두, 쉬기는 맞바꾸지 않고 다음 차례에 풀림, 없는 자리 거절, 역할 문구(다르게 보기의 탈출구, 되짚기의 후속 질문, 말 꺼내기의 들은 이야기), Recap 라벨과 겹치지 않음, 화두 문구 규칙, 저장·네트워크·마이크 API를 쓰지 않음. 직접 해 볼 테스트를 대신하지 않는다.

## 직접 해 볼 테스트

1. **화면 흐름:** 이름 하나만 적고 시작 → 세 칸에 역할이 하나씩 겹치지 않게 뜬다. "다음 차례"를 세 번 누르는 동안 각 칸이 세 역할을 한 번씩 거친다. 한 칸에서 "이번엔 쉬어요" → 그 칸만 흐려지고 다른 칸의 역할은 그대로, 다음 차례에 풀린다. "역할 없이 계속" → "역할 다시 켜기" → 같은 배정이 돌아온다. "끝내기" → "처음으로" → 이름 칸이 비어 있다.
2. **기록 없음:** 개발자 도구의 Network 탭과 Application 탭(Local Storage, Cookies)을 열어 둔 채 1을 반복한다 → 페이지 파일 외의 요청과 저장 항목이 없다.
3. **효과 비교 (팀 안):** 팀원 3명이 같은 주제로 15분은 역할 없이, 15분은 역할을 켜고 대화한다. 각 구간이 끝날 때마다 종이에 "나와 다른 의견을 들은 횟수"와 "생각이 조금이라도 바뀐 순간이 있었나(예/아니오)"를 적어 비교한다. 역할 3개가 대화를 끊을 만큼 무거웠는지도 적는다. **시간:** 각 구간에서 대화가 5초 이상 끊긴 횟수와, "더 할 말이 없다"고 처음 느낀 시점(화면의 "모임 N분")을 각자 적는다. 대화하지 않는 한 사람(또는 팀 밖 관찰자)이 녹음 없이 **누가 누구에게 말을 거는지**를 메모해, 두 사람끼리만 주고받고 한 사람이 관객이 되는지 본다. 역할을 공평하게 돌린 3인 실험에서도 두 사람끼리만 통한 경우가 많았기 때문이다 (Galantucci 외 2012, 비언어 게임). 종이 질문은 Recap의 회고와 겹치지 않게 앱 밖 테스트 도구로만 쓴다.
4. **시범 모임:** 3의 결과를 보고 11월 시범 모임에 가져가, 끝난 뒤 참여자에게 같은 두 질문과 "역할이 도움이 됐나, 거슬렸나"를 묻는다.
5. **45분 시간 실험 (시범 모임):** 낯선 세 사람이 화두 하나와 역할 돌리기(Facilitator도 함께 켜도 됨)로 45분 동안 대화한다. 관찰자가 녹음 없이 대화가 5초 이상 끊긴 횟수와 그때의 "모임 N분"을 적고, 끝난 뒤 참여자에게 "시간이 길었다 / 적당했다 / 짧았다"와 "언제부터 할 말이 줄었나"를 묻는다. 45분은 Aron 외(1997)의 2인 실험 시간에 맞춘 것일 뿐 정답이 아니다. 화두 질문 3개를 다 쓴 시점도 함께 적는다.

### 연구 확인 뒤 다시 정한 것 (2026-10-30, 모두 에이전트 추천안 수락)

구현 뒤 문피아가 두 가지를 제기했다. ChatGPT와의 대화는 "실패" 화두로 시작했는데 설계에 화두가 없었고, 제품을 실제 논문과 실험 결과에 맞춰 짜고 싶다는 것이었다. 그래서 1차 출처를 확인한 뒤(`RESEARCH.md`) 아래를 다시 정했다.

| 질문 | 결정 | 근거 |
|---|---|---|
| 후속 질문을 어디에 | 되짚기에 붙임 ("궁금한 걸 하나 더 물어봐 주세요"). 별도 역할은 만들지 않음 | Huang 외 2017 (후속 질문만 호감 예측, 2인 대상) |
