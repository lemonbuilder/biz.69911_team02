## Facilitator

대화가 깊어질 수 있도록, 더 진솔한 나를 나눌 수 있도록, 서로를 더 잘 알아갈 수 있도록 질문을 던집니다.
이 질문에 답하는 것으로 대화를 시작할 수 있습니다. 원하지 않으면 그냥 편하게 대화하셔도 돼요.

- 첫 질문은 가볍게 시작합니다. 불리고 싶은 이름과 함께 한 사람씩 돌아가며 답해 보세요.
- 대화가 끊기면 "다음 질문"을 누르세요. 나눈 이야기에 맞춰, 세 사람 모두 답할 수 있는 질문을 건넵니다.
- 가벼움 · 중간 · 깊음 중 얼마나 깊이 들어갈지는 여러분이 정합니다. 언제든 되돌릴 수 있어요.
- 답하고 싶은 만큼만 답하세요. 넘기고 싶은 질문은 "이 질문 넘기기"를 누르면 됩니다.
- 앱은 먼저 끼어들지 않습니다. 질문은 앱이 건네지만, 대화는 여러분의 것입니다.
- 대화를 듣는 것은 세 사람이 모두 동의했을 때만입니다. 언제든 "듣기 멈춤"을 누를 수 있고, 모임을 끝내면 이 기기의 기록을 지웁니다.

이 소개는 앱 첫 화면(동의 화면) 위쪽과 프로토타입 README 맨 앞에 그대로 쓴다.

## 누구를 위한 것인가, 문제가 드러나는 순간

- **대상:** 진짜대화의 3인 모임에 처음 만난 사이로 앉은 참여자 세 명.
- **순간 1:** 자리에 앉았는데 첫 마디를 누가 어떻게 꺼낼지 모르는 어색한 침묵.
- **순간 2:** 대화가 끊기거나, 직장·날씨 같은 얕은 이야기만 맴돌고 더 들어가지 못할 때.

## WhyTree에서 맡는 노드

- **주 노드:** 대화가 깊어지게 하기 (`[씨앗] 좋은 질문 던지기`의 바로 위)
- **그 위:** 처음 만난 사람과 속 깊은 대화 나누기 (수렴점)

## 원칙

- 대화는 사람이 나누고, 앱은 질문을 건넬 뿐이다.
- AI는 듣기만 하고 말하지 않는다. 앱이 먼저 끼어들지 않고, 사람이 누를 때만 질문을 띄운다.
- 언제 깊은 이야기로 갈지는 사람이 정하고, 언제든 되돌릴 수 있다.
- **마이크 방식은 팀 합의 전 실험이다.** `docs/PROJECT.md`는 "온라인과 AI는 대화 바깥에서만", "테이블 위의 대화는 사람에게만 맡긴다"고 적고 있다. 대화를 듣고 외부로 보내는 설계는 이 원칙을 바꾸는 일이다. 시범 모임에서 참여자에게 "듣는 앱"과 "탭하는 앱"(P1 키워드 탭 입력) 중 어느 쪽이 편했는지 묻고, 그 결과로 팀이 정한다.

## 사용자가 하는 일 (단계별)

1. 노트북 Chrome에서 질문 페이지를 연다. 노트북은 테이블 한쪽 끝에 두고 세 사람이 반원으로 앉는다.
2. 동의 화면에서 고지 문구를 읽고 "참여자 1·2·3" 칸을 각자 체크한 뒤 시작한다. 한 명이라도 원하지 않으면 "마이크 없이 시작"을 누른다.
3. 첫 질문(아이스브레이킹)이 크게 뜨고, "불리고 싶은 이름과 함께, 한 사람씩 돌아가며 답해 보세요"라는 안내가 붙는다.
4. 대화하는 동안 앱은 받아 적기만 한다. 화면 구석에 듣기 상태가 보인다.
5. 대화가 끊기거나 이어 갈 화제가 필요하면 누군가 "다음 질문"을 누른다. 직전 3분의 대화를 바탕으로 만든 질문이 뜬다. 질문이 마음에 안 들면 "이 질문 넘기기"를 누른다.
6. 단계 표시 [가벼움 | 중간 | 깊음]에서 아무 칸이나 눌러 단계를 오르내린다. 단계를 바꾸면 이전 질문은 사라지고 바뀐 단계에 맞는 새 질문이 바로 뜬다.
7. 누구든 "듣기 멈춤"을 누르면 마이크가 꺼지고 받아 적은 글이 지워진다. 이후에는 고정 질문으로 계속한다.
8. 모임이 끝나면 "모임 끝내기"를 누르고 확인 창에서 한 번 더 확인한다. 이 기기에 있는 받아 적은 글과 질문 기록이 모두 지워진다.

## 질문 규칙

### 두 종류의 질문

| 종류 | 언제 | 어디서 오나 |
|---|---|---|
| 사전질문 | 모임을 시작할 때, 첫 마디를 위해 | 사람이 쓴 아이스브레이킹 세트에서 무작위 (AI 사용 안 함) |
| 중도질문 | "다음 질문" / "이 질문 넘기기"를 누를 때 | 직전 3분의 받아 적은 글 + 현재 단계를 AI에 보내 생성 |

- **다음 질문:** 지금 화제를 세 사람 모두 답할 수 있게 일반화해서 이어 가는 새 질문.
- **이 질문 넘기기:** 같은 맥락과 단계에서 다시 뽑기. 첫 질문(아이스브레이킹)을 넘기면 AI 없이 다른 아이스브레이킹 질문을 뽑는다.
- AI를 부를 때는 지금 화면에 있는 질문을 함께 보내, 같은 질문이 다시 나오지 않게 한다.

### 세 단계의 기준

| 단계 | 무엇을 묻나 | 예시 |
|---|---|---|
| 가벼움 | 최근의 구체적인 사실·취향. 생각하지 않고 10초 안에 답할 수 있어야 한다. 감정·의미·이유는 묻지 않는다 | 오늘 점심은 무엇을 드셨나요? |
| 중간 | 그 선택의 이유, 아끼는 것 | 꾸준히 이어 오고 있는 일이 있다면 무엇인가요? |
| 깊음 | 전환점·고민·의미. 드러낼 범위는 답하는 사람이 고른다 | 최근 생각이 바뀐 일이 있다면 무엇인가요? |

- AI는 현재 단계 안에서만 질문을 만든다. 프롬프트에 단계마다 예시 2개를 넣는다.
- 깊음 단계 질문 아래에는 "답하고 싶은 만큼만, 넘어가도 괜찮아요"를 작게 고정해 둔다.

### 좋은 질문의 기준

- 예/아니오로 끝나지 않는 열린 질문
- 세 사람 모두 자기 경험으로 답할 수 있는 질문
- 정답이 없고, 평가받는 느낌이 들지 않는 질문
- 깊음 단계에서도 고백을 요구하지 않는다

### 문장 규칙 (AI 프롬프트에 그대로 넣는다)

- 존댓말 한 문장, 40자 안팎
- 특정인을 지목하지 않고 테이블 전체에 던진다 (앱은 누가 말했는지 구분하지 않는다)
- 대화에 나온 주제를 이어받되, 그 이야기를 하지 않은 사람도 답할 수 있게 한 단계 일반화한다. 특정 사람이 한 이야기의 후속 질문을 하지 않는다.
- 대화에서 들은 건강·연애·회사 이름 같은 민감한 내용을 질문에 옮기지 않는다. 받은 글을 인용하거나 요약해 출력하지 않는다.
- 받아 적은 글이 짧거나 뜻이 분명하지 않으면, 대화 내용에 기대지 말고 현재 단계의 일반 질문을 만든다.

### 사전질문 세트의 기준

- 직업·회사·나이·사는 곳을 묻지 않는다 (서열 비교와 직장 이야기 쏠림을 막기 위해).
- 30초 안에 답할 수 있는 가벼운 질문만 쓴다.
- 10~15개. (구현: 12개)

### 고정 질문 세트

- 단계마다 10개 이상. 같은 모임에서는 중복 없이 내고, 다 쓰면 처음부터 다시 쓴다. (구현: 단계마다 12개)
- 위 단계 기준과 문장 규칙을 따른다.
- 고정 질문은 앞선 대화 없이 단독으로 뜨므로 "그 일", "그때"처럼 앞 맥락을 가리키는 말을 쓰지 않는다.

## 화면

- 질문은 한 번에 한 개만 크게 보인다. 질문 글자는 48px 이상, 화면 폭 80% 안에서 두 줄 이내.
- 버튼:
  - "다음 질문": 하단 가운데의 주 버튼
  - "이 질문 넘기기": 작은 글자 버튼
  - 단계 표시 [가벼움 | 중간 | 깊음]: 아무 칸이나 눌러 오르내림. 다른 단계를 누르면 그 단계의 새 질문을 바로 띄운다("다음 질문"과 같은 규칙: 조건이 맞으면 AI, 아니면 고정 질문). 지금 단계를 다시 누르면 아무 일도 없다.
  - "듣기 멈춤": 작고 중립적인 문구. 멈춘 뒤에는 "다시 듣기"로 바뀐다.
  - "모임 끝내기": 다른 버튼과 떨어진 구석에 작게. 누르면 "모임을 끝내고 기록을 지울까요? [끝내기] [계속하기]" 확인 창이 한 번 뜬다.
- 버튼 글자는 질문 글자의 절반 이하.
- **듣기 상태:** 화면 위 구석에 움직이지 않는 점과 글자로 표시하고, 실제 인식 상태를 따른다: "듣는 중" / "다시 연결 중" / "듣지 않음".
- **대기 중:** 질문을 만드는 동안 이전 질문을 흐리게 남겨 두고 "질문을 고르는 중…"을 작게 표시한다. "다음 질문", "이 질문 넘기기", 단계 버튼만 잠근다. "듣기 멈춤"과 "모임 끝내기"는 언제든 누를 수 있어야 하므로 잠그지 않는다.
- **끝 화면:** "모임이 끝났습니다. 이 기기에 있던 대화 기록을 지웠습니다."와 "새 모임 시작" 버튼. 새 모임은 동의 화면부터 다시 시작한다.
- **대체 질문:** 화면 아래 구석에 회색 작은 글자로 "기본 질문"이라고 표시한다.
- **받아 적은 원문은 어떤 경우에도 화면에 띄우지 않는다.**
- **테스트용 숫자**(재시작 횟수, 분당 받아 적은 글자 수)는 평소에 숨기고, `D` 키를 누를 때만 보인다. 개발자 도구 콘솔에서 `facilitatorDebug()`로 버퍼 길이와 듣기 상태를 볼 수 있다.

> 음성은 글자로 바꾸기 위해 Google 서버로, "다음 질문"을 누를 때 직전 3분의 글은 질문을 만들기 위해 Anthropic(미국)으로 보내집니다.
> 이 기기에는 저장하지 않으며, 끝내면 지웁니다. 다만 외부로 보낸 데이터는 각 회사의 정책에 따라 처리됩니다.
> 건강·연애 같은 민감한 이야기도 받아 적혀 보내질 수 있습니다.
> 언제든 "듣기 멈춤"을 누를 수 있습니다. 동의하지 않아도 기본 질문으로 모임을 할 수 있습니다.

- "참여자 1·2·3" 칸이 모두 체크되어야 "시작"이 켜진다.
- 같은 크기의 "마이크 없이 시작" 버튼을 함께 둔다. 이 경우 고정 질문으로만 진행한다.
- "듣기 멈춤" 뒤 다시 켜려면 세 명이 다시 동의해야 한다.

## AI 모델과 실패했을 때

### 음성 → 글자

- Chrome Web Speech API, `lang='ko-KR'`, `continuous=true`, `interimResults=false`.
- 인식을 시작하기 전에 `getUserMedia`로 마이크 권한을 한 번 받는다. 권한을 기다리는 동안에는 "마이크 권한 기다리는 중"을 표시하고 인식·재시작·감시를 시작하지 않는다. 거부하면 고정 질문 모드로 바꾼다.
- 인식은 침묵·네트워크·시간 제한으로 저절로 끊긴다. `onend`가 나면 0.5초 → 1초 → 2초로 간격을 늘려 가며 다시 시작한다. 15초 동안 아무 이벤트가 없으면 `abort()` 후 다시 시작한다.
- `not-allowed` 오류(마이크 권한 거부)가 나면 재시작을 멈추고 고정 질문 모드로 바꾼다. 브라우저가 음성 인식을 지원하지 않을 때도 고정 질문 모드로 시작한다.
- 마이크는 보안 출처에서만 허용되므로 노트북 Chrome에서 `http://localhost`로만 연다.

### 직전 3분 버퍼

- 확정된 인식 결과만 `{시각, 글}` 배열로 담는다.
- 30초마다 180초가 지난 항목을 지운다.
- 버튼을 누를 때 합계가 30자 미만이면 AI를 부르지 않고 현재 단계의 고정 질문을 띄운다.

### 질문 생성

- Claude Haiku 5.5 (`claude-haiku-5-5`). 버튼을 누르고 몇 초 안에 질문이 떠야 해서 빠른 모델을 쓴다.
- API 키는 브라우저에 두지 않고, 작은 Node 서버가 대신 호출한다 (`/api/question`).
- 화면은 `AbortController`로 5초, 서버는 Claude 호출에 4.5초 제한을 둔다(재시도 없음). `max_tokens` 120. 5초 뒤에 도착한 답은 버린다.
- Haiku 5.5는 기본으로 생각(thinking)을 켜서, 120토큰 안에 질문이 잘리거나 늦어질 수 있다. 질문 한 문장에는 생각이 필요 없으므로 `thinking: {type: "disabled"}`로 끈다.
- 받은 질문이 한 문장이 아니거나, 60자를 넘거나, 물음표로 끝나지 않으면 고정 질문으로 바꾼다.

### 실패하면

아래 중 하나라도 해당하면 현재 단계의 고정 질문을 띄우고 "기본 질문"으로 표시한다.

- 음성 인식이 안 될 때 (권한 거부, 지원하지 않는 브라우저)
- 네트워크가 끊길 때 (이때는 받아 적기도 함께 멈춘다)
- AI가 5초 안에 답하지 않거나, 답이 문장 규칙 검사를 통과하지 못하거나, 답을 거절(refusal)할 때
- 받아 적은 글이 30자 미만일 때
- API 키가 없을 때 (서버가 즉시 `{source: 'fallback'}`을 돌려준다)

## 범위 밖

- 관심주제 찾기 (별도 씨앗)
- 받아 적은 글이나 질문을 사람 조합·필터링에 쓰는 것
- 세 사람이 각자 폰으로 쓰는 앱
- 모임 중 앱이 먼저 끼어들기 (침묵 감지 등)
- 다른 기기(태블릿 등)에서 노트북 서버에 접속하기 (마이크 보안 조건 때문)
- 출시 수준의 법무 요건 (개인정보 처리방침, 국외이전 고지 등)

## 구현

- 위치: `prototypes/박혜민/`
- 웹 페이지 하나 + API 키를 숨기는 작은 Node 서버. 팀원 프로토타입(`prototypes/정직한/`)의 express + `@anthropic-ai/sdk` + `.env` 구조를 따른다.
- 포트는 3100 (`http://localhost:3100`). 팀원 프로토타입의 3000과 겹치지 않게.
- API 키는 `.env`에 넣는다. 비워 두면 고정 질문만으로 동작한다.
- 자동 테스트(`npm test`): 키 없는 경로, 입력 검사, AI 답 검사, 고정 질문 세트가 기준을 지키는지. 직접 해 볼 테스트를 대신하지 않는다.
- 구현 순서:
  1. 고정 질문과 화면 (키 없이도 완성)
  2. 동의, 듣기 멈춤, 끝내기와 삭제
  3. 받아 적기와 자동 재시작
  4. `/api/question`과 Claude 연결
- 1~2만으로 테스트 1과 3을 통과한다. 테스트 2·4는 API 키를 받은 뒤 한다.
- 비상안: 받아 적기가 늦어지면 P1의 키워드 탭 입력을 대신 쓴다.

## 직접 해 볼 테스트

> **API 키: 향후 발급(예정).** 지금은 `.env`의 키를 비워 둔 상태로, 테스트 1과 3만 확인할 수 있다. 테스트 2·4·5(AI 맞춤 질문)는 키를 발급받아 `.env`에 넣은 뒤 확인한다.

1. **키 없이:** API 키 없이 서버를 띄운다 → 동의 화면, 첫 질문, 단계 오르내리기, 단계별 고정 질문이 정상으로 나오고 "기본 질문" 표시가 보인다. "마이크 없이 시작"도 같은 흐름으로 진행된다.
2. **맞춤 질문:** 한 주제(예: 여행)로 2~3분 이야기한 뒤 "다음 질문"을 누른다. 3번 중 2번 이상, 질문에 그 주제어나 관련어가 들어가고 5초 안에 뜬다. 질문은 문장 규칙을 지킨다.
3. **동의와 삭제:** 세 칸이 모두 체크되기 전에는 마이크가 켜지지 않는다. "듣기 멈춤"과 "모임 끝내기" 뒤에는 탭의 마이크 표시가 꺼지고, 개발자 도구 콘솔에서 `facilitatorDebug().bufferLength`가 0이다.
4. **쏠림 방지:** 한 사람이 2분 동안 혼자 자기 이야기를 한 뒤 "다음 질문"을 누른다 → 그 사람의 개인사를 파고들지 않고, 세 명 모두 답할 수 있는 질문이 나온다.
5. **오래 쓰기:** 세 명이 노트북에서 1m 거리에 앉아 20분 대화한다 → `D` 키로 재시작 횟수와 분당 받아 적은 글자 수를 확인하고, 듣기 표시가 실제 상태와 맞는지 본다.

### 테스트 결과 (2026-10-28, Chrome 156, 키 없음)

| 테스트 | 결과 |
|---|---|
| 1. 키 없이 | 통과. 동의 화면(세 칸 전에 "시작" 꺼짐), 첫 질문과 안내, 넘기기, 단계별 고정 질문과 "기본 질문" 표시, 깊음 안내 문구 |
| 3. 동의와 삭제 | **첫 시도 실패 → 수정 후 통과.** 권한 창이 떠 있는 동안 인식 재시작이 돌아 "허용"이 반영되지 않았다. 권한을 먼저 받도록 고친 뒤 "듣는 중" 전환, "듣기 멈춤" 후 버퍼 0과 "다시 듣기", "모임 끝내기" 확인 창과 삭제를 확인 |
| 받아 적기 (테스트 2·4·5의 전제) | **미해결.** 마이크 소리(최대 음량 0.6)와 말소리 감지(`speechstart`)까지는 되지만, Chrome 서버 인식이 결과를 돌려주지 않아 20초 동안 0자. 네트워크(VPN·방화벽)가 막는지 확인 못 함. 대안은 기기 안 인식(P1, 한국어 언어팩 "다운로드 가능" 확인)이나 비상안인 키워드 탭 입력 |
| 2·4·5 | API 키 발급 후, 받아 적기 문제를 해결한 뒤 확인 예정 |

위 결과는 에이전트와 함께 시연하며 확인한 것이다. 그 뒤 수정한 내용(단계를 바꾸면 새 질문, 가벼움 질문 세트, Facilitator 소개 문구)까지 반영된 화면에서 **테스트 1과 3을 박혜민이 직접 다시 실행해 통과를 확인했다** (2026-10-28, 새 Chrome 창, `http://localhost:3100`).
